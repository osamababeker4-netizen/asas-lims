# مختبر أساس LIMS — Web V7.1 Central

نسخة ويب عربية RTL متقدمة مبنية على أساس LIMS، وتحتوي على وحدات المختبر وإدارة المشاريع والعينات والاختبارات والتقارير والأجهزة وNCR والمستخدمين والتدقيق، بالإضافة إلى **بلدي — رخص الحفريات**.

## ما الجديد في V7.1
- Central API مستقل ببايثون وSQLite بدون مكتبات خارجية.
- مصادقة مركزية: كلمة مرور PBKDF2 + جلسة موقعة HMAC + OTP لمدة 5 دقائق.
- صلاحيات أدوار أساسية (admin / reviewer / technician / user).
- سجل تدقيق مركزي.
- مزامنة Local-First مع رقم إصدار وحماية من تعارض النسخ (HTTP 409).
- قاعدة بيانات WAL لتحسين التزامن المحلي.
- PWA/واجهة RTL متجاوبة للجوال والكمبيوتر.
- نسخ احتياطي واستعادة من الواجهة.
- وحدة بلدي ورخص الحفريات محفوظة ضمن المشروع.

## التشغيل المحلي
يتطلب Python 3.9+.

```bash
python server.py
```
ثم افتح:

`http://localhost:8080`

لا توجد كلمة مرور افتراضية منشورة. عند أول تشغيل اضبط `ASAS_BOOTSTRAP_PASSWORD` لإنشاء حساب المدير. وإذا لم يُضبط، يطبع الخادم كلمة مرور عشوائية لمرة واحدة في طرفية التشغيل.

## ملاحظة أمنية مهمة
هذه الحزمة **جاهزة للتطوير والتجهيز والنشر بعد إعداد بيئة الاستضافة** وليست شهادة اعتماد Production. قبل الاستخدام الفعلي يجب:
1. تغيير كلمة مرور المدير الافتراضية.
2. وضع الخدمة خلف HTTPS وReverse Proxy.
3. ربط OTP بمزود SMS حقيقي. لا يعيد الخادم OTP إلا عند ضبط `ASAS_DEV_RETURN_OTP=1` في بيئة تطوير محلية.
4. استخدام PostgreSQL أو خدمة قاعدة بيانات مركزية مُدارة عند التوسع.
5. تفعيل إدارة أسرار/متغيرات بيئة ومراقبة ونسخ احتياطي دوري.
6. تنفيذ اختبار أمني واختبار قبول قبل الاعتماد الرسمي.

## مزامنة Android الميداني

المزامنة محلية أولاً: تسجيل العينة أو النتيجة أو الجهاز أو NCR أو حالة التقرير أو تصريح الحفر يكتب في SQLite على الهاتف ثم يضاف إلى `sync_queue`. لا يؤدي انقطاع الشبكة إلى فقد أي عملية.

1. شغّل الخدمة خلف HTTPS (للتطوير المحلي يمكن تشغيل `python server.py`).
2. من شاشة **المزامنة المركزية** في Android أدخل أصل الرابط، مثل `https://lims.example.sa` (لا تضع `/api` في آخره).
3. أدخل بيانات حساب الخادم، اضغط طلب رمز OTP ثم تحقق واربط الحساب. يحفظ التطبيق رمز الجلسة ضمن مساحة التطبيق الخاصة.
4. اضغط **رفع الطابور الآن**. العمليات الناجحة تصبح `SYNCED`، وأخطاء الشبكة تصبح `RETRY`، وأخطاء المصادقة `FAILED`، والتعارضات تحفظ في `sync_conflicts` للمراجعة.

واجهة الرفع هي `POST /api/sync/queue` وتتطلب `Authorization: Bearer <token>`. يقبل الخادم دفعات حتى 100 حدث ويستخدم `(deviceId, queue id)` كمفتاح idempotency، لذلك تكرار طلب انقطع أثناء الاستلام لا ينشئ سجلاً ثانياً.


## تكامل واتساب وتلجرام — V7.1
- مركز مراسلات داخل النظام مع مفهوم Draft First.
- واتساب: فتح محادثة برسالة جاهزة عبر wa.me، والإرسال الآلي عبر WhatsApp Business Cloud API عند ضبط متغيرات البيئة.
- تلجرام: مشاركة الرسالة كمسودة، والإرسال الآلي عبر Telegram Bot API عند ضبط TELEGRAM_BOT_TOKEN.
- زر **إرسال كمسودة** في كل تقرير: يُنشئ ملخص النتيجة في مركز المراسلات قبل فتح أي تطبيق خارجي.
- رابط قناة واتساب الرسمية قابل للإدارة من صفحة الإعدادات.
- لا يتم وضع مفاتيح API داخل ملفات الواجهة أو المستودع.
- متغيرات الخادم: WHATSAPP_ACCESS_TOKEN وWHATSAPP_PHONE_NUMBER_ID وTELEGRAM_BOT_TOKEN.

## كتالوج الاختبارات وخطة العينة
- كتالوج منظم لاختبارات التربة والخرسانة والأسفلت، يَظهر كاملاً في صفحة الاختبارات.
- عند تسجيل عينة من إحدى المواد الثلاث، ينشئ النظام كامل **خطة اختبارات معلّقة** مرتبطة بالعينة دون حدّ عددي ودون إنشاء نتائج مزيفة.
- عند حفظ نتيجة اختبار، تُعلَّم خانته في الخطة كمكتملة ويُنشأ التقرير المعتاد، فيما تبقى جميع العينات والنتائج والتقارير المحفوظة سابقاً دون تعديل.
- رموز ASTM مرجعية لتصنيف العمل داخل النظام؛ لا تغني عن النسخ المعتمدة من المواصفات وإجراءات الجودة المعمول بها في المختبر.
